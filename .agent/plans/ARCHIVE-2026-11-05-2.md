# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/sites/site_name.rs
**Purpose:** Read and check the site names of a block's coverage: the grammar of one domain name and the list limits.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -rn -i -e hostname -e subdomain -e sites core/src` shows only a doc comment in models/specs.rs; no code reads or checks a domain name, so a new reader is needed.
**Failure paths:** An empty list, a list over 1000 names, a name over 253 characters, a non-text entry, or any name outside the grammar (URL, port, wildcard, uppercase, IP number) is refused with the field and index named; a huge list is refused before it is walked, never a panic.
**Criterion:** AC-002: a block can cover sites and every other site text refuses the whole zip naming file and field

### core/src/sites/site_match.rs
**Purpose:** Say whether a host is covered by a block's listed sites: the name itself or any subdomain of it.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -rn -i -e ends_with -e host core/src` shows no host matching anywhere in the core, only unrelated string checks, so the matcher is new.
**Failure paths:** An empty host, a host that only ends with the same letters (notinstagram.com), a name that merely contains a listed one (instagram.com.example.org) and an empty site list are all not covered; upper case and one trailing dot are ignored; nothing panics.
**Split justification:** Matching a host against a list is a separate job from reading a file: the browser extension and the decision loop call it with no settings file in sight, and it has its own tests.
**Criterion:** AC-003: a host is covered by a listed domain or its subdomains and lookalike hosts are not

### core/src/domain/extended_schema.rs
**Purpose:** Hold the extended schema, the phone's format-2 schema plus the additions Leko Enforcer reads, parsed once.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -rn -e bundled_schema -e include_str core/src` shows only domain/schema_fields.rs, which embeds the pinned format-2 file; the extended file is a second, separate schema, so it needs its own loader.
**Failure paths:** The file is embedded at build time so it cannot be missing at run time; if it ever failed to parse the schema is null and the judge's table reports a sentence instead of panicking.
**Split justification:** Loading a schema file is a separate job from reading site names; it lives with the other schema loader in domain/ and serves canonical form, the loosening table and the schema test, not only sites.
**Criterion:** AC-011: the extended schema file differs from the pinned format-2 schema only in the listed places

### core/src/sessions/utc_moment.rs
**Purpose:** Read and write the one moment form the additions use, UTC as YYYY-MM-DDTHH:MM:SSZ, for session ends and moment seals.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -rn -e "fn parse_iso" -e "fn is_real_date" core/src` shows only calendar dates (YYYY-MM-DD) in zone_time.rs and strict_fields.rs; nothing reads or writes a time of day in UTC, so a moment parser is new.
**Failure paths:** An offset, a missing Z, a lower-case t or z, February 30, a :60 second, hour 24, a wrong width, a sign or any non-digit is refused; writing an instant outside years 0 to 9999 gives nothing; no panic on any text.
**Split justification:** Moment parsing and writing is shared by the session reader, the seal reader and the session maker, and holds no settings-file code, so it is a small file of its own beside the readers that use it.
**Criterion:** AC-005: a session rule is read with endsAt a UTC moment that is a real date and bad moments refuse

### core/src/sessions/session_rule.rs
**Purpose:** Read the fields of a session rule (endsAt, and no days) and the moment fields that a moment seal shares with it.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -n -e "fn read_rule" -e "fn read_stretches" -e "KINDS" core/src/config/read_block.rs` shows the kind-by-kind rule reading is in read_block.rs, which has no session kind and is near the size where more reading belongs in its own file.
**Failure paths:** A days list, a missing endsAt, a non-text endsAt or any bad moment is refused with the rule path and field named; the phone's mode never reaches this code.
**Split justification:** read_block.rs reads the phone's kinds only; session reading is a new kind that the seal reader also needs for its moment, so it lives in its own feature folder.
**Criterion:** AC-005: a session rule is read with endsAt a UTC moment that is a real date and bad moments refuse

### core/src/sessions/session_compare.rs
**Purpose:** Judge sessions by time: which rules are in force at a moment (an ended session is no rule) and whether a changed session loosens.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -n -e "pub fn loosens" -e "pub fn by_id" core/src/config_diff/rule_compare.rs core/src/config_diff/diff_parts.rs` shows rule comparison and keying take no moment, so an ended session cannot be left out there.
**Failure paths:** A session whose endsAt cannot be read counts as one that loosens when changed; ending at exactly the moment of the change counts as ended; rules that are not sessions are never dropped; no panic on odd JSON.
**Split justification:** Time-aware judging of one rule kind is a separate job from comparing rule fields, and ended sessions must be dropped before rules are keyed by id.
**Criterion:** AC-006: a session is judged by when it ends and one that has ended counts as no rule

### core/src/sessions/timed_session.rs
**Purpose:** Make a session rule and a moment seal that end at the same instant, from the current moment and a number of minutes.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -rn -e "pub fn due" -e "pub fn seal_end" -e "Utc::now" core/src` shows the judge reads locks and never builds them, and only the time module may read the clock, so a maker must take the moment as an argument.
**Failure paths:** 0 minutes, a negative number, more than 10080, a sum that overflows, or an end past year 9999 is refused with a sentence; a part of a second rounds up so the session is never short; the clock is never read.
**Split justification:** Building a session is a separate job from reading or judging one: it takes a moment as an argument and returns values.
**Criterion:** AC-009: the session maker returns a rule and a seal that end at the same moment and refuses bad minutes

### core/src/domain/extension_fields.rs
**Purpose:** List every place a settings file uses a field the phone 0.3 does not read, so an export can name the blocks the phone would refuse.
**Feature:** site-coverage-and-sessions
**Existing code checked:** `grep -n "pub fn" core/src/domain/schema_fields.rs core/src/domain/set_rules.rs` shows functions over the pinned schema and rule sets, none that finds uses of fields outside it.
**Failure paths:** A document that is not an object, a covers or lock that is not an object, a rules list with non-objects, and a level that is not text all give an empty list for that part; no panic on any JSON.
**Split justification:** Finding new-field uses works on parsed documents and is called by the export, which is a different job from reading a file or judging a change.
**Criterion:** AC-010: a function lists every place a settings file uses a new field
