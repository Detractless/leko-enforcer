This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/status/next_flip.rs
**Purpose:** Finds the first moment after a given one at which one app or website flips between closed and open, looking eight days ahead by the minute and at every session end of the blocks that cover it.
**Feature:** status-command
**Existing code checked:** `grep -rn -e next_change -e LOOK_AHEAD_DAYS core/src` shows only decision/next_change.rs, which reports any change of any rule of any on block and takes no target, so a target-aware search over the covering blocks is needed.
**Failure paths:** Nothing flipping within eight days gives none; a target no block covers or a never-blocked app gives none; a moment so large that the look-ahead would overflow gives none; a rule opening while another still closes is not a flip.
**Criterion:** AC-006: the next flip is the first moment the answer for that target differs, found by the minute for eight days and at each session end

### cli/src/status/status_arguments.rs
**Purpose:** Reads the words after `leko status` into one request: the settings file, one app or site, an optional zone and the JSON switch, or the one-sentence problem with them.
**Feature:** status-command
**Existing code checked:** `grep -n -e split_flags -e read_arguments cli/src/session/session_arguments.rs` shows the session command's flag reader, which knows only --json and --id and returns a session request, so a separate reader for the status flags is needed.
**Failure paths:** A missing, repeated, unknown or empty argument, neither or both of --app and --site, and two files are each a sentence and no request; no file is opened here.
**Criterion:** AC-003: wrong or missing status arguments print the usage and one plain sentence on stderr, make no answer and exit 2
**Split justification:** This file only turns words into a request; settings_file.rs reads the file and run_status.rs runs the request, and neither belongs in an argument reader.

### cli/src/status/zone_choice.rs
**Purpose:** Chooses the time zone a status answer is judged in: the one named by --zone, else the computer's zone handed in, and a sentence when neither is usable.
**Feature:** status-command
**Existing code checked:** `grep -rn -e ZoneTime::new -e computer cli/src core/src/config_time` shows ZoneTime::new in the core and no zone choice anywhere in the command-line crate.
**Failure paths:** An unknown zone name gives the core's sentence; no zone flag and no computer zone gives a sentence asking for --zone; an unknown computer zone gives a sentence asking for --zone; UTC is never assumed.
**Criterion:** AC-004: the zone flag beats the computer's zone and an unknown or missing zone gives no answer
**Split justification:** The choice of zone has its own rules (flag first, never UTC by guess) and its own refusals, separate from reading arguments and from reading the file.

### cli/src/status/settings_file.rs
**Purpose:** Reads the settings zip named on the command line into the core's settings, refusing a missing, unreadable, empty, oversize or refused file with a plain sentence.
**Feature:** status-command
**Existing code checked:** `grep -rn -e check_zip -e fs::read cli/src` finds nothing, so the command-line crate reads no file yet; the core's check_zip takes bytes.
**Failure paths:** A missing path, a folder, an unreadable file, a file over 64 MB (refused by its size before reading), an empty file, a non-zip and a zip the core refuses each give a sentence and no settings.
**Criterion:** AC-009: a file that cannot be read or is refused gives no answer and exit 1
**Split justification:** This is the only file that touches the disk; keeping it apart keeps the argument reader and the report free of file reads.

### cli/src/status/status_report.rs
**Purpose:** Writes what the command says about one answer: the sentence for a person with local times and the one JSON line for a script with UTC times, both built from the same values.
**Feature:** status-command
**Existing code checked:** `grep -n -e pub\ fn cli/src/session/session_report.rs` shows the session sentence, JSON line and refusal text, which are about a made session and cannot say closed or open.
**Failure paths:** An odd or long app name or host is written safely with shown; an answer that never flips says it holds for at least eight days; a refusal sentence always says nothing was saved or changed.
**Criterion:** AC-001: the sentence says closed or open with every closing block and rule, the moment and zone, and that nothing was saved or changed
**Split justification:** This file only turns an answer into text; run_status.rs gathers the answer and settings_file.rs reads the file.

### cli/src/status/run_status.rs
**Purpose:** Runs one `leko status` request: reads the file, chooses the zone, asks the core at the given moment, writes the result to the right stream and returns the exit code.
**Feature:** status-command
**Existing code checked:** `grep -n -e pub\ fn -e EXIT_ cli/src/session/run_command.rs` shows run, the exit codes and the stream helpers for the session command only.
**Failure paths:** Bad arguments exit 2 before any file is read; a zone or file problem exits 1 with nothing on stdout; a stdout that cannot be written exits 1 with a sentence on stderr; nothing is saved.
**Criterion:** AC-010: results go to stdout and errors to stderr, exit 0 answers, 1 cannot answer, 2 not understood, and nothing is changed
**Split justification:** This file only joins the other status files in order; it holds no parsing, zone, file or text logic of its own.
