# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/io/zip_writer.rs
**Purpose:** Writes a list of named files as a zip that the core's own reader and any ordinary unzip tool read back with the same names and contents.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e write_zip -e DeflateEncoder -e ZipWriter core/src cli/src` shows nothing, so the core can read zips (zip_reader.rs) but has no way to write one; the test helper in core/tests/zip_writer builds zips only for tests.
**Failure paths:** An empty list, a name used twice, more than 500 files, a file over 1 MB, or a total over 64 MB gives the same sentence the reader gives for it and writes nothing.
**Criterion:** AC-012: the core writes a zip that its reader and an independent tool both read back the same, and refuses lists its own reader would refuse

### core/src/blocks/block_request.rs
**Purpose:** Holds the words of a request to add a block (name, apps, sites, rule, door, message) as plain values, so the command line, a voice layer and a model all fill in the same thing.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e BlockRequest -e RuleChoice -e DoorChoice core/src cli/src` shows nothing; models/specs.rs holds blocks as they are read from a file, not a request to make one.
**Failure paths:** The type holds values only and checks nothing; the checks are in draft_block.rs and the readers, so an empty or odd value is judged in one place.
**Criterion:** AC-003: the core builds the block from the request alone, and the same request gives the same block
**Split justification:** The request is the shared input of the drafter, the adder and the command line; keeping it apart stops the command line depending on how a block is built.

### core/src/blocks/block_id.rs
**Purpose:** Makes the id of a block from its name by one fixed rule and refuses a name that cannot make a valid id or is unsafe to write.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e is_item_id -e MAX_ID core/src` shows the id check in config/read_block.rs and nothing that makes an id from a name.
**Failure paths:** An empty name, a name over 60 characters, a name with a control character, and a name with no ASCII letter or digit each give a sentence and no id; an id over 64 characters is cut.
**Criterion:** AC-003: the id comes from the name by a fixed rule, and an empty, long, control-character or letterless name is refused with a sentence
**Split justification:** The id rule is its own small rule with its own refusals, used by the drafter and by the report that shows the id.

### core/src/blocks/draft_block.rs
**Purpose:** Turns a block request and the current moment into the block file's JSON, with the rule, door, pass, message and seal each written as the readers expect, and refuses a request the readers could not read.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e make_timed_session -e outsideHours core/src` shows the session maker (sessions/timed_session.rs) and the readers of rules; nothing builds a whole block.
**Failure paths:** A wait over 600 seconds, a message over 300 characters or with a control character, a timed block with a wait door, a session length the session maker refuses, and no app and no site each give a sentence and no block.
**Criterion:** AC-004: each rule kind is written so that reading it back and asking the decision gives what the words say
**Split justification:** This file builds one block; the zip work and the file checks live in add_block.rs.

### core/src/blocks/add_block.rs
**Purpose:** Adds a drafted block to the bytes of a settings zip: refuses a zip the core refuses or an id already used, writes the new zip, checks the result in the extended and the phone's reading, and returns the new bytes and any phone warning.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e check_zip_in_mode -e open_zip core/src cli/src` shows the reader and checker only; nothing combines a draft with an existing zip.
**Failure paths:** A zip the core refuses, a block id already in the zip (on or off), a result the core refuses, and a zip that already holds the most files each give a sentence and no bytes; the input bytes are never changed.
**Criterion:** AC-002: the drafted block is added as its own file and every other file keeps its name and content
**Split justification:** This file works on whole zips; draft_block.rs works on one block and zip_writer.rs on zip bytes.

### cli/src/add_block/add_block_arguments.rs
**Purpose:** Reads the words after `leko add-block` into one request: the settings file, the name, the apps and sites, exactly one rule, the door, the message and the write switch, or the one-sentence problem with them.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e read_status_arguments -e split_flags cli/src` shows the status and session flag readers, which know other flags and return other requests, so a reader for these flags is needed.
**Failure paths:** A missing, repeated, unknown or empty argument, no target, no rule or two rules, a bad day, a bad time stretch, a bad length, a wait and a wall together, and two files are each a sentence and no request; no file is opened here.
**Criterion:** AC-009: wrong or missing add-block arguments print the usage and one plain sentence on stderr, read no file and exit 2
**Split justification:** This file only turns words into a request; the run file orders the work and the report file writes the sentences.

### cli/src/add_block/add_block_report.rs
**Purpose:** Writes what the command says: the plain draft of the block, the sentence after a save, and the phone warning, all built from the values the core returned.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e pub\ fn cli/src/status/status_report.rs cli/src/session/session_report.rs` shows the sentences for a made session and a status answer, neither of which can describe a block to be added.
**Failure paths:** An odd or long name, app or site is shown through the existing safe quoting; a block with no rule words is never printed, because the drafter always writes one.
**Criterion:** AC-001: the draft names the block, what it covers, the rule, the door, and says nothing was saved
**Split justification:** The wording is separate from the order of work and from the argument reader, and it is the part most likely to change.

### cli/src/add_block/file_replace.rs
**Purpose:** Replaces a file with new bytes in one step: writes a temporary file beside it, flushes, copies the permissions, and moves it over the old one, leaving the old file whole if anything fails.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e fs::rename -e fs::write -e create_new cli/src core/src` shows nothing; the command line has never written a file.
**Failure paths:** A folder that cannot be written, a write that fails part-way, a flush or permission copy that fails, and a move that is refused each remove the temporary file, keep the old file byte for byte and give a sentence; a link is followed to the file it points to.
**Criterion:** AC-011: a failed save leaves the old file and no temporary file, and a good save keeps the permissions and the link
**Split justification:** This is the only new file that writes to the disk; keeping it apart keeps the other add-block files free of file writes.

### cli/src/add_block/run_add_block.rs
**Purpose:** Runs one `leko add-block` request in order: read the words, read the settings file, build the draft, then show it or, with the write switch, save it, writing results to stdout and errors to stderr.
**Feature:** add-block-command
**Existing code checked:** `grep -rn -e run_status -e write_result cli/src` shows the status runner and the stream helpers it uses, which this runner reuses, but nothing runs an add-block request.
**Failure paths:** Arguments not understood give exit 2 before any file is touched; a file, a core refusal, an id already used or a failed save give exit 1 with nothing on stdout; a closed stdout after a save keeps the save and gives exit 1.
**Criterion:** AC-013: results go to stdout, errors to stderr, and the exit code says which happened
**Split justification:** The runner orders the steps; the arguments, the wording and the disk work are in their own files.
