# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/delayed_changes/waiting_change.rs
**Purpose:** Holds one parked change (a switch-off of one block, the moment it was asked for and the moment it may land) and writes and reads those moments as UTC text.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e WaitingChange -e requestedAt -e dueAt core/src cli/src` shows nothing; sessions/utc_moment.rs reads and writes the moment text, which this file reuses, but nothing holds a parked change.
**Failure paths:** A moment that is not whole-second UTC text, a block id the readers would refuse, or a due moment before the request moment is refused with a sentence, and no record is made.
**Criterion:** AC-011: a waiting record reads back to the same moments, and an odd record is refused

### core/src/delayed_changes/waiting_file.rs
**Purpose:** Reads and prints the waiting file's JSON (format 1, one record per parked change) strictly, refusing a newer format, a missing or unknown field and a block listed twice.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e waiting_file -e "format\": 1" core/src cli/src` shows nothing; the settings readers in config/ read blocks and routines, not a queue of changes.
**Failure paths:** Empty text, text that is not JSON, a JSON value that is not an object, a format number other than 1, an unknown or missing field, and a repeated block each give one reason sentence and no list.
**Criterion:** AC-011: a file this version wrote reads back to the same records, and a newer or odd one is refused whole
**Split justification:** The file format is its own rule, read and written by two commands; the record type lives in waiting_change.rs.

### core/src/delayed_changes/switch_off_plan.rs
**Purpose:** Decides what switching one block off means at a moment: sends the change through the loosening judge, gathers the block's own lock and the locks of routines that hold it, and answers lands now, waits until a moment, cannot land, needs a partner key, already off or no such block.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e diff_item -e "fn due(" core/src cli/src` shows the judge (config_diff/item_diff.rs) and the due moment (config_time/due_time.rs), used only by tests so far; nothing calls them for a real change.
**Failure paths:** An id no block has, a block already off, a partner key on any applied lock, change windows that share no minute and a due moment past the year 9999 each give their own answer and no write.
**Criterion:** AC-001: the core decides a switch-off through the judge and each kind of lock gives its moment
**Split justification:** This file decides; block_off_zip.rs changes the zip and settle_plan.rs decides later, with the same locks.

### core/src/delayed_changes/block_off_zip.rs
**Purpose:** Returns the bytes of a settings zip with one block's file set to off and every other file as it was, checking the result with the core's reader before giving it back.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e write_zip -e check_zip core/src` shows the writer and the checker used by blocks/add_block.rs, which only adds a new file; nothing changes a field of an existing block.
**Failure paths:** A zip the core refuses, a block that is not in the zip, a block file that is not a JSON object, and a result the core would refuse each give a sentence and no bytes; the input is never changed.
**Criterion:** AC-004: the block goes off, nothing else in the zip changes and the saved zip passes the check
**Split justification:** Changing one field of an existing file is a different job from adding a file (add_block.rs) and from deciding (switch_off_plan.rs).

### core/src/delayed_changes/settle_plan.rs
**Purpose:** Decides for each parked change whether it lands, is not due yet, is cleared or is stopped, judging the block as it is now and never earlier than the saved due moment, and returns the new zip bytes and the changes still waiting.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e settle -e SettleStep core/src cli/src` shows nothing; the only code that knows locks and due moments is the judge and due_time.rs.
**Failure paths:** A removed or already-off block clears its record; a partner key added later, windows with no shared minute, a clock earlier than the request or a lock tightened since keep the record and say why; a zip the core refuses gives a sentence and no change.
**Criterion:** AC-014: settle judges the block as it is now and never lands early
**Split justification:** Settling re-judges parked work against the present file, which is a different moment and input from the first request in switch_off_plan.rs.

### cli/src/delayed_changes/delay_arguments.rs
**Purpose:** Reads the words after leko switch-off and leko settle into a request: the settings file, the block id for switch-off, an optional zone name and the write switch, refusing anything else in one sentence.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e switch-off -e SwitchOff cli/src` shows nothing; status/status_arguments.rs reads a different command, whose flags and help differ.
**Failure paths:** A missing file, a missing or repeated id, a repeated or empty zone, an unknown flag, a second file and an id given to settle each give a one-sentence problem and no request; no file is opened.
**Criterion:** AC-008: wrong or missing arguments print usage and exit two for both commands
**Split justification:** Both commands share one small word reader; the command files only act on a request that is already understood.

### cli/src/delayed_changes/waiting_file_disk.rs
**Purpose:** Finds the waiting file beside a settings file, reads it from disk with a size limit, and turns any problem into one plain sentence that names the file safely.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e MAX_TOTAL_BYTES -e read_settings_bytes cli/src` shows status/settings_file.rs reads the settings zip with a size guard; it does not read a waiting file or handle a file that is not there yet.
**Failure paths:** No file means nothing is waiting; an empty file, a directory, an unreadable file, a file over the limit and text the core refuses each give a sentence and are never overwritten.
**Criterion:** AC-009: a bad waiting file is reported and nothing is overwritten
**Split justification:** The waiting file is a second file with its own missing-file rule; settings_file.rs must keep refusing a missing settings zip.

### cli/src/delayed_changes/switch_off_report.rs
**Purpose:** Writes the sentences of leko switch-off: the draft for a change that lands now or must wait, the saved and parked sentences, and the already-off and already-waiting sentences, each with the local moment and the lock behind it.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e draft_text -e saved_text cli/src` shows add_block_report.rs writes the sentences of a new block; none of them speak of a lock or a wait.
**Failure paths:** The functions only build text; a moment that cannot be shown in the zone is written in UTC and the text says so, so no sentence is ever empty.
**Criterion:** AC-003: the draft says when the change lands in the local zone and which lock makes it wait
**Split justification:** Words for the user are kept apart from the steps that read and save files, as add_block_report.rs is kept apart from run_add_block.rs.

### cli/src/delayed_changes/run_switch_off.rs
**Purpose:** Runs one leko switch-off request in order: words, zone, settings file, waiting file, the core's plan, then the draft or, with the write switch, the saved zip or the parked record.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e run_add_block -e run_status cli/src` shows the two existing runners; neither judges a loosening nor writes a second file.
**Failure paths:** Not-understood words exit 2 before any file is read; a refused request exits 1 with one line ending Nothing was saved; a save that fails leaves both files as they were.
**Criterion:** AC-005: a locked change is parked in the waiting file and the settings zip is not touched
**Split justification:** This is the runner of a different command; it shares the save step and the file reader but none of the add-block steps.

### cli/src/delayed_changes/settle_report.rs
**Purpose:** Writes the sentences of leko settle: nothing waiting, what is not yet due and why, the draft of what would land, the saved result and the halfway failure.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e Nothing -e waiting cli/src` shows only the add-block and status sentences; no sentence lists waiting changes.
**Failure paths:** The functions only build text; every outcome of the core (lands, not due, cleared, stopped) has its own sentence, so none is left silent.
**Criterion:** AC-012: settle lists what is not due, with why, and says nothing is waiting when so
**Split justification:** Settle's words differ from switch-off's and are tested on their own.

### cli/src/delayed_changes/run_settle.rs
**Purpose:** Runs one leko settle request: reads the settings and waiting files, asks the core what lands, and with the write switch saves the zip first and the shortened waiting file second.
**Feature:** delay-block-change
**Existing code checked:** `grep -rn -e replace_file -e RealSteps cli/src` shows the save step is used only by run_add_block.rs; no code saves two files in order.
**Failure paths:** No waiting file says nothing is waiting and makes no file; a failed zip save keeps the waiting file as it was; a failed waiting-file save after the zip is reported and a second run finishes cleanly.
**Criterion:** AC-015: a failed second save is reported and a rerun finishes the job
**Split justification:** Settle is a separate command with a two-file save order; run_switch_off.rs writes one file at a time.
