# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/waiting_changes/cancel_waiting.rs
**Purpose:** Takes the parked change of one block out of a list of parked changes, keeping every other record exactly as it was and in order, and says whether a record was removed or none was there.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -i -e cancel -e retain core/src cli/src` shows only the session reader's list of denying words and one `retain` over session rules; nothing removes a parked change.
**Failure paths:** An id that is only a prefix of another block's, a different case, or path-shaped text matches no record, and a list with no record for the id comes back unchanged with "none was there".
**Criterion:** AC-001: cancelling removes only that block's record and keeps the rest in order

### core/src/waiting_changes/waiting_for_target.rs
**Purpose:** Picks, from the parked changes, the ones whose block covers an app or a site and gives each the settle step `leko settle` would give it, in file order, from the settings alone.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -e "covers(" -e outcome_of core/src cli/src` shows `covers` used by `decide_target.rs` and `next_flip.rs` for closing rules only, and `outcome_of` private to `settle_plan.rs`; nothing joins a parked change to a target. This file reuses both (the second becomes public).
**Failure paths:** A change whose block is no longer in the settings, or whose block does not cover the target, is left out; a block that covers the target but is off or outside its hours still counts; no target match gives an empty list.
**Criterion:** AC-002: only changes of blocks that cover the target come back with what settle would say
**Split justification:** This file joins changes to a target; settle_plan.rs judges a change and cancel_waiting.rs removes one, and each is used by a different command.

### cli/src/waiting_changes/cancel_arguments.rs
**Purpose:** Reads the words after `leko cancel` into one request: the settings file, the block id and the write switch; a missing, repeated, unknown or odd word is a one-sentence problem and no request.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -e read_delay_arguments -e "fn once" cli/src` shows `delay_arguments.rs` reading `switch-off` and `settle`, which take `--zone`; cancel takes no zone, and adding it there would give that file a third command with different flags.
**Failure paths:** No file, no `--id`, `--id` twice or without a value, `--write` twice, an unknown flag (also `--zone`) and a second file each give one sentence and no request.
**Criterion:** AC-007: bad arguments print the usage line and exit two
**Split justification:** `delay_arguments.rs` already carries the zone choice and two commands; the cancel words are a different, smaller set.

### cli/src/waiting_changes/cancel_report.rs
**Purpose:** Builds the sentences of `leko cancel`: the draft, the saved result, and "nothing is waiting"; each ends with a newline and names the block safely.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -e "Nothing is waiting" -e "fn draft" cli/src` shows `settle_report.rs` with its own "nothing is waiting" and draft sentences for the whole list; cancel's are about one block and say "Cancelled", so they are not reused.
**Failure paths:** An odd or long block id is written with `shown`, so it cannot flood or steer the terminal; the draft names the same command with `--write`.
**Criterion:** AC-003: the draft says what would be cancelled and saves nothing
**Split justification:** These are the words a person reads; `run_cancel.rs` decides what happens, and keeping the sentences apart lets a test check them without a disk.

### cli/src/waiting_changes/run_cancel.rs
**Purpose:** Runs one `leko cancel` request in order: the words (exit 2), the waiting file beside the settings file (exit 1 when it is bad), the core's cancel, then the draft or, with `--write`, one atomic save of the shortened waiting file.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -e read_waiting_changes -e save_waiting cli/src` shows both used by `run_switch_off.rs` and `run_settle.rs`; this file reuses them and the save step in `file_replace.rs`, and never opens the settings zip.
**Failure paths:** A waiting file that is bad is reported and left as it was; nothing waiting for the id saves nothing and makes no file; a failed write, flush or move leaves the file as it was with one sentence and exit 1.
**Criterion:** AC-004: write removes only that record and never touches the settings zip
**Split justification:** This file is the order of steps and the exit codes; the argument reader and the sentences are separate files with their own tests.

### cli/src/waiting_changes/status_waiting.rs
**Purpose:** Reads the waiting file beside the settings file for `leko status` and builds the extra lines and the JSON list for the parked changes of the blocks that cover the asked app or site, using settle's own wording.
**Feature:** waiting-list-and-cancel
**Existing code checked:** `grep -rn -e waiting cli/src/status` shows nothing; `status_report.rs` builds the sentence and the JSON line from a decision only, and `settle_report::step_line` already holds the wording.
**Failure paths:** No waiting file means no lines and an empty list; a bad one means no lines, a `null` list and one sentence for stderr; the file is only read, never made or changed.
**Criterion:** AC-010: status lists the waiting changes of the blocks that cover the target
**Split justification:** `status` and `cancel` both need the waiting file, but only status joins it to a target and builds JSON; the cancel files do neither.
