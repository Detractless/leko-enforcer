# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/switch_on/plan_switch_on.rs
**Purpose:** Decides from the settings alone what switching one block on means: there is no such block, it is already on, or it lands now; no lock, key or moment is looked at because switching on is a tightening.
**Feature:** switch-on
**Existing code checked:** `grep -rn -e plan_switch_off -e "fn applied_locks" core/src cli/src` shows the switch-off plan judging locks and moments; nothing plans a switch-on. The test pins that the loosening judge calls `on` false to true a tightening, so this file needs no lock code.
**Failure paths:** An unknown id gives "no such block"; a block with `on` true or no `on` field is "already on"; a block with every kind of lock still lands now.
**Criterion:** AC-001: a switch-on lands at once whatever locks the block has

### core/src/switch_on/block_on_zip.rs
**Purpose:** Gives the bytes of a settings zip with one block's file set to `"on": true`, every other field, block and file unchanged and in order; the new zip is read again before it is returned.
**Feature:** switch-on
**Existing code checked:** `grep -rn -e switch_block_off -e "fn refused" core/src` shows `block_off_zip.rs` doing the same for `"on": false`; its zip check is reused (made visible to the crate), its wording is not, since the refusals differ.
**Failure paths:** An unknown block, a block already on, a zip the core refuses, a block file that is not a JSON object, or a rewritten zip the core would refuse each give a sentence and no bytes.
**Criterion:** AC-002: only the on field of that block changes and the new zip is read again
**Split justification:** The plan decides what a switch-on means from the settings; this file rewrites the zip bytes, and each is tested and used apart.

### cli/src/switch_on/switch_on_arguments.rs
**Purpose:** Reads the words after `leko switch-on` into one request: the settings file, the block id and the write switch; a missing, repeated, unknown or odd word is a one-sentence problem and no request.
**Feature:** switch-on
**Existing code checked:** `grep -rn -e read_cancel_arguments -e read_delay_arguments cli/src` shows `cancel_arguments.rs` reading the same three words with a cancel-only sentence for a missing id; its reader is split so both commands share one loop and only the missing-id sentence differs.
**Failure paths:** No file, no `--id`, `--id` twice or without a value, `--write` twice, an unknown flag (also `--zone` and `--json`) and a second file each give one sentence and no request.
**Criterion:** AC-009: bad arguments print the usage line and exit two

### cli/src/switch_on/switch_on_report.rs
**Purpose:** Builds the sentences of `leko switch-on`: the draft, the saved result, "already on", and the stop while a switch-off of the block is parked; each ends with a newline and names the block safely.
**Feature:** switch-on
**Existing code checked:** `grep -rn -e "already switched off" -e "fn already_off" cli/src` shows `switch_off_report.rs` with the sentences of the other direction; these say "on", name `leko cancel`, and are not shared.
**Failure paths:** An odd or long block id is written with `shown`; the stop names the exact `leko cancel` command with the file and id quoted for a shell.
**Criterion:** AC-003: the draft says what would happen and saves nothing
**Split justification:** These are the words a person reads; `run_switch_on.rs` decides what happens, and keeping the sentences apart lets a test check them without a disk.

### cli/src/switch_on/run_switch_on.rs
**Purpose:** Runs one `leko switch-on` request in order: the words (exit 2), the settings file (exit 1), the waiting file (exit 1 when bad), the core's plan, then the draft or, with `--write`, one atomic save of the settings zip; the waiting file is read, never written.
**Feature:** switch-on
**Existing code checked:** `grep -rn -e read_settings_and_bytes -e read_waiting_changes -e save_file cli/src` shows all three used by `run_switch_off.rs`; this file reuses them and writes only the zip.
**Failure paths:** A bad zip or waiting file, an unknown block, a parked switch-off of the same block, and a failed write, flush or move each give one sentence ending "Nothing was saved" or naming the step, and leave both files as they were.
**Criterion:** AC-004: write changes only that block's on field and leaves the waiting file alone
**Split justification:** `run_switch_off.rs` carries the zone choice and the wait; this command has no moment and a different order, and the two would share nothing but the reused readers.
