# Active plan: one "### <path>" entry per new code file (format: .agent/plans/TEMPLATE.md)
<!-- contract-required -->
This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### cli/src/session/session_length.rs
**Purpose:** Turn the typed length text (90, 90m, 2h, 7d) into a whole number of minutes, counting without overflow.
**Feature:** session-command
**Existing code checked:** `grep -rn -e MAX_SESSION_MINUTES -e "fn make_timed_session" core/src` shows the core takes whole minutes from 1 to 10080 as a number and judges the range, but nothing turns text such as 2h into minutes, so the length reader is new.
**Failure paths:** Empty text, a sign, a decimal point, two units, a capital unit, non-ASCII digits or any other non-digit is not a length; a number too big to count is saturated to the largest number so the core refuses it by range instead of the program crashing.
**Criterion:** AC-002: a length is whole minutes or one whole number with m, h or d and out-of-range or too-big lengths exit 1

### cli/src/session/session_arguments.rs
**Purpose:** Read the program arguments into one request: the command, the flags, the length or the heard words, or a usage problem.
**Feature:** session-command
**Existing code checked:** `grep -rn -i -e args_os -e std::env -e "--json" core/src` found nothing: the core is pure and never sees program arguments, so the argument reader is new.
**Failure paths:** No command, an unknown command or flag, a flag given twice, a flag without a value, a wrong number of lengths, an empty command line or an argument that is not valid text each give a one-sentence usage problem and make no request; nothing is guessed.
**Split justification:** Reading arguments is a separate job from turning length text into minutes and from running the command; it holds the flags and the usage line and is tested on its own.
**Criterion:** AC-003: wrong or missing arguments print a usage line on stderr and exit 2 while help prints on stdout

### cli/src/session/voice_phrase.rs
**Purpose:** Read the words a speech-to-text heard into one length in minutes, or refuse with the reason when it is unclear or asks for the opposite.
**Feature:** session-command
**Existing code checked:** `grep -rn -i -e voice -e spoken -e phrase core/src` found nothing: no code reads spoken words, so the phrase reader is new.
**Failure paths:** Empty text, text over 500 characters, no session word, no length, two lengths, a stray number, an unknown unit, a number in words, zero, a minus or a decimal, half in another form, or any cancelling or denying word makes nothing and says why; no panic on any text.
**Split justification:** Reading free words is a different job from reading a typed length and has its own small grammar and word lists; it is the part the future voice layer will call.
**Criterion:** AC-007: a phrase that is unclear or asks for the opposite makes nothing and exits 2

### cli/src/session/session_report.rs
**Purpose:** Write the result of a made session as the sentence a person reads or as the one JSON line a script reads.
**Feature:** session-command
**Existing code checked:** `grep -rn -e "pub struct TimedSession" -e ends_at core/src` shows the core hands back the rule, the seal and the end as values, but nothing writes them as a sentence or one line, so the report writer is new.
**Failure paths:** A session of 1 minute is written in the singular; the JSON line is built from the core's own rule and seal values so it cannot differ; a value that cannot be written is not possible because the text comes from values already made.
**Split justification:** Writing the result is a separate job from reading arguments and from running the command; both output forms are tested here against the core's values.
**Criterion:** AC-005: json is one line holding the rule and the seal the core makes and without json the sentence only

### cli/src/session/run_command.rs
**Purpose:** Run one command line: read the request, make the session at the given moment, write to the two streams and return the exit code.
**Feature:** session-command
**Existing code checked:** `grep -rn -e "fn run(" -e ExitCode -e process::exit core/src` found nothing: the core has no program entry, so the command runner is new.
**Failure paths:** A usage problem or a phrase not understood gives exit 2 on stderr; a refusal by the core gives exit 1 on stderr; an output that cannot be written gives exit 1 without a panic; nothing is read from or written to disk.
**Split justification:** Joining the readers, the core's session maker and the streams is the one place that decides exit codes and which stream gets what; the readers stay free of output.
**Criterion:** AC-009: results go to stdout and errors to stderr with exit 0 for made, 1 for refused and 2 for not understood

### cli/src/lib.rs
**Purpose:** List the modules of the command-line crate and export the one function the program and the tests call.
**Feature:** session-command
**Existing code checked:** `grep -rn -e "pub mod sessions" -e "pub use" core/src/lib.rs` shows the core's own module list; the command-line crate is a separate package and has no library file of its own yet.
**Failure paths:** It holds no logic, only module lines and one re-export, so it has no input to fail on; the build fails if a module named here is missing.
**Split justification:** A library file lets the tests call the run function with a fixed moment while main.rs stays a thin start-up that reads the clock.
**Criterion:** AC-011: the clock is read in one place only, main.rs, and every other file gets the moment as an argument
