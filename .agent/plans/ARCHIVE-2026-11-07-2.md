This project builds new features under contracts (.agent/contracts/<feature>.md). A new code file needs an entry here whose
Feature has an open contract and whose Criterion names one of that contract's acceptance criteria.

### core/src/edit_block/coverage.rs
**Purpose:** Applies named app and site operations to a validated settings zip without changing unrelated fields.
**Feature:** edit-block-command
**Existing code checked:** `rg -n switch_block_on core/src` shows the existing validated zip rewrite pattern.
**Failure paths:** Missing blocks, invalid coverage, conflicting operations, and invalid resulting zips are refused without changed bytes.
**Criterion:** AC-002: the edit changes only named coverage and refuses invalid requests.

### core/src/edit_block/edit_plan.rs
**Purpose:** Judges coverage edits and computes waits using the current block and holding routine locks.
**Feature:** edit-block-command
**Existing code checked:** `rg -n applied_locks core/src` finds the existing lock collection for block changes.
**Failure paths:** Unreadable canonical data, required keys and incompatible locks cannot bypass the loosening judge.
**Criterion:** AC-003: the edit uses the judge and all applicable locks.
**Split justification:** Judging locks and rewriting zip bytes have distinct responsibilities and independently testable failures.

### cli/src/edit_block/edit_arguments.rs
**Purpose:** Parses named coverage edit arguments without touching settings or operating-system state.
**Feature:** edit-block-command
**Existing code checked:** `rg -n read_add_block_arguments cli/src` identifies the existing command argument parser.
**Failure paths:** Missing values, repeated flags, contradictory operations and unknown arguments produce usage errors.
**Criterion:** AC-001: the edit command accepts explicit coverage operations.
**Split justification:** Argument parsing is separate from file operations and lock decisions.

### cli/src/edit_block/run_edit_block.rs
**Purpose:** Coordinates coverage edit preview, lock planning, and explicit atomic saves or queueing.
**Feature:** edit-block-command
**Existing code checked:** `rg -n read_waiting_changes cli/src` finds the existing waiting file reader used by change commands.
**Failure paths:** Invalid zip or queue, conflicting waiting records, refused locks and failed saves leave existing files intact.
**Criterion:** AC-005: edits that wait are parked without changing settings.
**Split justification:** The command's disk effects and output differ from pure parsing and core planning.
